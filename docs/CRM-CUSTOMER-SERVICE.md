# Native CRM CustomerService adapter

`Factuarea.customerService` is the handwritten native v1 subset below, composed with the SDK's existing authentication, error decoding, request metadata and `AbortSignal`. Generated resources, the pinned specification and package version remain separately managed.

| Node method | Native endpoint | Confirmation |
| --- | --- | --- |
| `get` | GET `/crm/service-tickets/{id}` | HTTP200, current masked ticket |
| `list` / `iterate` | GET `/crm/service-tickets` | HTTP200, native offset page |
| `timeline` | GET `/crm/service-tickets/{id}/timeline` | HTTP200, historical parent/version under current masks |
| `moveToStage` | POST `/crm/service-tickets/{id}/move-to-stage` | HTTP200, original ticket CAS or CAS+1 |
| `attachDocument` | POST `/crm/service-tickets/{id}/attachments` | HTTP200, original ticket CAS+1 |
| `detachDocument` | POST `/crm/service-tickets/{id}/attachments/remove` | HTTP200, original ticket CAS+1 |

Responses retain `{data, status, headers, requestId}`. The outer native `{data}` JSON envelope is decoded once. Ticket/document/attachment/pipeline/stage/message IDs use UUIDv7. Native actor UUIDs retain their original version. `serviceTicketId` and `serviceTicketVersion` share the existing document brands, so a returned commercial document can be attached directly with its original version. Counts and CAS are safe integers; versions used for writes must leave room for CAS+1. These ticket endpoints contain no monetary fields. Native document amounts continue to use the existing exact decimal-string types; no amount, financial summary or delivery fact is inferred from a ticket.

Ticket, comment, attachment and historical snapshot fields preserve omission independently of null. Missing `attachments` means that the projection did not expose the list. An empty exposed list means an authorized empty list. `writable_fields` travels with its original `authorization_version`; the adapter does not grant field authority or manufacture defaults. Historical snapshots keep their own parent and version. Native enum strings in reads survive future server additions. The current owner exposes neither the waiting ledger nor a new public `waiting_reason` response field. The decoder tolerates an optional future waiting projection without requiring or fabricating it.

The stage request has `expected_version`, `pipeline_id`, `stage_id`, optional `waiting_reason` and optional `customer_message_id`. Omitted `waiting_reason` preserves the existing cause. `"waiting_customer"` requests a customer wait; the owner validates the stage mapping, current permissions and causal facts. Explicit null requests release. A non-null `customer_message_id` is permitted only with explicit `waiting_reason:null`, and identifies the original ticket comment from the customer, not a new outbound reply or an invented conversation identity. The owner validates visibility, participant, cycle and original occurrence time. Explicit null and omission remain distinct in the retained JSON.

Attachment writes are JSON references to an admitted native commercial document: `document_id` and `document_version`, plus the current ticket `expected_version`. The server chooses the attachment ID. The attach receipt contains only `{id,version}`. For detach, obtain `attachment_id` from an authorized ticket or timeline read and use the current ticket CAS. These operations accept no multipart bytes, Blob, URL, private storage handle, caller effect identity or company/actor/scope input.

Each write requires the caller's original ASCII `idempotencyKey` and attempts once, including when the SDK's default retry setting is higher. Timeout, connection loss, cancellation, ambiguous/revoked native errors and invalid success receipts throw `CustomerServiceWriteUnconfirmedError` with the original immutable `intent`, native request ID and typed `originalError`. Ordinary CAS conflict, field validation and technical rate-limit errors retain the SDK's existing native classes. Cancellation ends the local wait; a mutation may already have committed.

Explicit `customerService.recover(error.intent, {signal,timeout})` attempts only the original POST/path/JSON/key. The intent is sealed to its original client, credential/company/profile/version context and original request headers. Changed effective authentication context or forged/copied intents fail before network I/O. Recovery cannot replace the body, CAS or key and does not reload the current ticket to guess a result. Pass a fresh signal after cancellation. HTTP200 with an original matching receipt confirms recovery; queued, foreign, private, partial or wrong-CAS results remain unconfirmed. The public intent does not expose credentials or private headers. This in-memory intent does not provide restart persistence.

`iterate` copies its initial filters, retains native offset pagination, rechecks ACL on every read and has an explicit maximum of 1000 pages by default. It rejects no-progress pages or a reached limit instead of returning an incomplete list as complete. Offset pages do not constitute a consistent cross-page snapshot.

Contract authority: current CustomerService v1 controllers/resource/request boundary, Root's three native producer operations and the ticket waiting source freeze. PHP SDK frozen71 provides the semantic reference for the six operations, optional child masks and original receipt checks; its baseline predates the waiting fields handled here. `test/crm-customer-service.test.ts` uses offline native wire fixtures. It verifies the transport contract, not a running server or SQL persistence. Root still owns producer registration, scopes/capability/OpenAPI wiring, sandbox A/B validation, specification sync and release gates. This adapter does not activate production.
